# デメリット・注意点（正直ベース）

> Better Auth は強力だが万能ではない。弱点の多くは「新しい OSS であること」と「自前ホストであること」から来る。導入判断のために、ここでは欠点を誇張も矮小化もせず正直に並べる。

### 🎤 登壇メモ

- **つかみ**: 「いいことばかり並べる発表」は信用されない。だからこそ最後の章で正直に弱点へ踏み込む
- **強調**: 正直さが信頼を生む——弱点を隠さず語ることが、むしろ技術選定全体の説得力になる
- **10分なら**: デメリットは「歴史が浅い」と「自前ホストの運用責任」の2つに絞り、残りは口頭で軽く触れる

技術選定は強みだけ見て決めると後で痛い。以下は本番採用前に必ず評価しておきたい論点を、影響の大きい順に並べたものだ。

---

## 主要な注意点

### 1. 歴史が浅い

v1 はリリースされたものの、Clerk や Auth0 と比べるとエンタープライズでの採用実績はまだ薄い。**SOC2** などのコンプライアンス認証や、有償サポート・SLA といった体制もこれから整っていく段階だ。金融・医療のような規制業界では、監査や調達の要件を満たせるかを早めに評価しておく必要がある。

→ 競合との実績比較は [§00 比較](00-introduction.html) を参照。

### 2. 破壊的変更リスク

進化が速いぶん、本体やプラグインの API が予告なく動くことがある。本番運用では追従コストを織り込み、依存バージョンを固定する戦略（`package.json` でのピン留めや lockfile 厳守）が前提になる。アップデート時は CHANGELOG を読み、検証環境で先に試す運用フローを用意しておきたい。

→ 成熟度の前提は [§00 比較](00-introduction.html) を参照。

### 3. 自前ホスト = 運用責任は自分持ち

メール配信・スケール・セキュリティパッチの適用は、すべて自分の責任範囲になる。「全部おまかせ」でインフラを意識せずに済む Clerk とは、そもそも別物だと理解しておく必要がある。ただしこれは裏返せば、**自由**と**データ所有**を手に入れているということでもある。

→ 運用の重さを和らげる有料代替は [§06 Infrastructure](06-infrastructure.html) を参照。

### 4. プラグイン追従の手間

プラグインを追加するたびに、CLI の `generate` と `migrate` を再実行する必要がある。複数プラグインの組み合わせや読み込み**順序**でハマることがあり、エラーメッセージだけでは原因が見えにくいケースもある。導入時はプラグインを一つずつ足して、都度マイグレーションを確認するのが安全だ。

→ プラグインの仕組みと追加手順は [§03 プラグイン](03-plugins.html) を参照。

### 5. Infrastructure（有料）依存の芽

運用の一部を有料層（マネージドな Infrastructure）に寄せていくと、そこにロックインの芽が生まれる。便利だからと寄せすぎると、「自前ホストだから自由」という当初の利点が薄れていく。**コアは自前**で持ちつつ、どこまでを有料に委ねるかのバランスを設計段階で決めておきたい。

## 小さめの注意点

### 6. コミュニティプラグインの品質ばらつき

エコシステムのプラグイン数は多いが、玉石混交なのが実情だ。本番に採用するものは、メンテ状況・実装の中身・依存関係を自分の目で確認してから入れるべきだ。

### 7. TS/Node・RDB 前提が強い

設計の中心が TypeScript / Node と RDB に置かれており、非 TS 環境や NoSQL は一級市民ではない。MongoDB アダプタなどの選択肢はあるが、スタックが大きく外れる場合は別の認証基盤も併せて比較したほうがよい。

→ 対応 DB とアダプタの前提は [§05 データベース](05-database.html) を参照。

## 競合との位置づけ

| 観点 | Better Auth | Clerk / Auth0 |
|---|---|---|
| データ所有 | 自前（強み） | ベンダー側 |
| 運用責任 | 自分持ち（弱み） | おまかせ |
| エンタープライズ実績 | これから | 豊富 |
| 型安全・網羅性 | 強み | 限定的 |

---

> 弱点の多くは「新しい OSS であること」と「自前ホストであること」の裏返しにすぎない。**データ所有**・**型安全**・**網羅性**・**AI ネイティブ**という強みが、これらのコストを上回るかどうか——その一点で判断すればよい。
